# 管理员全局编辑权限变更设计

- 日期：2026-08-09
- 状态：待书面复核
- 影响范围：M0 权限基线及后续授权测试

## 1. 目标

管理员无需成为项目成员，即可在全部项目中新增、修改和逻辑删除业务记录。领导仍保持全部项目只读；普通用户仍按项目成员关系获得查看和编辑权限。

## 2. 权限范围

管理员全局拥有以下能力：

- 查看、创建和编辑项目基础资料。
- 新增、修改和逻辑删除合同、付款节点、回款、进度、里程碑、签证、造价版本、风险、待办、照片及附件元数据。
- 上传、预览和下载全部项目文件。
- 管理项目成员，归档和恢复项目。
- 管理账号、系统角色和系统配置。

以下能力不因全局编辑权自动开放：

- 单项目完整导出继续使用单独受控流程。
- 文件对象和业务记录的永久物理删除不提供普通业务接口。
- 生产审计记录不能由普通管理员修改或删除。
- 密码、令牌、密钥和其他敏感凭证不可读取。

## 3. 服务端判定

服务端先校验账号状态、会话、项目状态和输入合法性。通过后：

1. `ADMIN` 对全部项目获得业务读取和写入权限，不要求项目成员关系。
2. `LEADER` 对全部项目仅获得读取权限，写入仍要求 `OWNER` 或 `EDITOR` 成员关系。
3. `USER` 的读取和写入继续完全依据项目成员关系。
4. 导出、永久删除和审计维护继续执行独立的专项权限规则。

前端按钮显示不能替代上述服务端校验。

## 4. 离线同步

- 管理员桌面端只能离线编辑已经同步到本机的项目数据。
- 同步服务收到管理员操作时，按操作到达时的当前系统角色重新校验权限。
- 管理员角色被撤销或账号被停用后，尚未接受的全局编辑操作必须拒绝并停止自动重试。
- 合法并发修改仍采用记录级、服务器接收顺序的最后有效提交覆盖。

## 5. 审计

管理员跨项目新增、修改、逻辑删除、文件上传下载、成员调整和项目归档必须记录审计。审计包含操作者、项目、记录标识、操作类型、服务器时间及必要的字段摘要，不记录敏感凭证或完整文件内容。

## 6. 文档与测试变更

实施时同步修改：

- `README.md` 的用户与权限说明及验收口径。
- `TO-do.md` 的全局约束、M0 权限矩阵任务、M2 授权任务和验收项。
- `docs/architecture/permission-matrix.md` 的角色范围、判定顺序、业务矩阵、API 映射、示例和验收检查。

后续授权测试至少覆盖：管理员未加入项目仍可新增、修改和逻辑删除业务记录；管理员不能直接执行完整项目导出；管理员不能修改审计记录；管理员角色撤销后离线待同步操作被拒绝。

## 7. 完成标准

- 所有 M0 文档均明确管理员拥有全局业务编辑权。
- 不再出现“管理员必须加入项目才能编辑”的旧口径。
- 领导全局只读和普通用户按项目授权的规则保持不变。
- 完整导出、永久物理删除和审计保护边界没有被扩大。
- 权限矩阵示例可以唯一推导允许或拒绝结果。
