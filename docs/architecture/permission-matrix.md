# 权限矩阵与项目成员规则

## 1. 目的

本文定义项目管理线上版的首期授权规则。所有读取、修改、导出和文件访问均由 API 服务端校验；客户端展示控制只用于改善交互，不能作为安全边界。

## 2. 系统角色

| 角色 | 标识 | 默认数据范围 | 系统管理能力 |
| --- | --- | --- | --- |
| 普通用户 | `USER` | 仅本人参与的项目 | 无 |
| 领导 | `LEADER` | 全部项目只读 | 无 |
| 管理员 | `ADMIN` | 全部项目可读写 | 账号、角色、项目创建、成员授权、系统配置 |

领导如需编辑某项目，必须同时成为该项目的负责人或编辑成员。管理员无需加入项目即可新增、修改和逻辑删除全部项目业务数据。

## 3. 账号与凭证前置条件

| 账号状态 | 凭证状态 | 登录 | 读取 | 写入 | 同步 |
| --- | --- | --- | --- | --- |
| `ACTIVE` | `READY` | 允许 | 按权限允许 | 按权限允许 | 允许 |
| `ACTIVE` | `PENDING_ACTIVATION` | 拒绝 | 拒绝 | 拒绝 | 拒绝 |
| `ACTIVE` | `RESET_REQUIRED` | 拒绝 | 拒绝 | 拒绝 | 拒绝 |
| `DISABLED` | 任意 | 拒绝 | 拒绝 | 拒绝 | 拒绝并撤销会话 |

系统不提供公开注册。所有受保护操作的共同前置条件是账号已启用且凭证已就绪。管理员创建账号、启用账号、停用账号和签发激活或重置一次性码；用户自行设置密码，管理员不能设置、读取或导出用户密码。

## 4. 项目成员角色

| 项目成员角色 | 标识 | 查看项目 | 编辑业务 | 管理成员 | 归档项目 |
| --- | --- | --- | --- | --- | --- |
| 项目负责人 | `OWNER` | 是 | 是 | 是 | 是 |
| 编辑成员 | `EDITOR` | 是 | 是 | 否 | 否 |
| 查看成员 | `VIEWER` | 是 | 否 | 否 | 否 |

规则：

- 一个项目至少有一名有效的 `OWNER`。
- 只有管理员可以创建项目；创建时必须指定首位 `OWNER`。
- `OWNER` 可以增加、调整和移除 `EDITOR`、`VIEWER`，但不能移除最后一名 `OWNER`。
- 管理员可以调整所有项目成员，用于组织变更和账号交接。
- 项目归档是可恢复操作；项目永久删除首期不提供业务接口。
- 归档项目保持原有读取权限，仅 `OWNER` 或管理员可以恢复。

## 5. 权限判定顺序

服务端按以下顺序判定，每一步失败立即拒绝：

1. 账号状态必须为 `ACTIVE`，凭证状态必须为 `READY`；否则拒绝并按需要撤销会话。
2. 会话必须有效、未过期且未撤销。
3. 根据当前角色和项目成员关系计算操作权限。
4. 对需要审计的允许操作写入结构化审计记录。

1. 账号必须为 `ACTIVE`。
2. 会话必须有效且未撤销。
3. 请求所属项目必须存在且未物理清理。
4. `LEADER`、`ADMIN` 获得项目读取权；普通用户必须具有有效项目成员关系。
5. 业务写操作允许 `ADMIN` 直接通过；其他角色必须具有 `OWNER` 或 `EDITOR` 成员关系。
6. 成员管理、归档、恢复、导出等敏感操作再检查专项权限。
7. 文件访问必须同时通过文件记录和所属项目的权限检查。

项目成员关系是普通用户和领导的业务编辑权来源；`ADMIN` 的全局业务编辑权是第 5 步的显式例外。

## 6. 业务权限矩阵

符号：

- `R`：查看
- `C`：新增
- `U`：编辑
- `D`：逻辑删除或移除
- `E`：导出或下载
- `M`：管理成员或系统配置
- `-`：不允许

| 资源 | 查看成员 `VIEWER` | 编辑成员 `EDITOR` | 项目负责人 `OWNER` | 领导（非成员） | 管理员（非成员） |
| --- | --- | --- | --- | --- | --- |
| 项目基础资料 | R | RCU | RCU | R | RCU |
| 项目成员 | R | R | RCMUD | R | RCMUD |
| 合同及付款节点 | R | RCUD | RCUD | R | RCUD |
| 回款与结算 | R | RCUD | RCUD | R | RCUD |
| 进度与里程碑 | R | RCUD | RCUD | R | RCUD |
| 签证 | R | RCUD | RCUD | R | RCUD |
| 造价及版本 | R | RCUD | RCUD | R | RCUD |
| 风险 | R | RCUD | RCUD | R | RCUD |
| 待办 | R | RCUD | RCUD | R | RCUD |
| 照片与附件元数据 | R | RCUD | RCUD | R | RCUD |
| 文件预览与下载 | E | E | E | E | E |
| 单项目完整导出 | - | - | E | - | - |
| 项目归档与恢复 | R | R | RU | R | RU |
| 审计日志 | - | - | R | R | R |
| 用户账号 | - | - | - | - | RCMU |
| 系统角色与配置 | - | - | - | - | RMU |

补充规则：

- 表中的管理员 `D` 表示逻辑删除业务记录或移除项目成员，不表示永久物理删除。
- 管理员跨项目新增、修改、逻辑删除、成员调整和项目归档必须记录审计。
- 领导和管理员下载文件的行为必须进入审计日志。
- 单项目完整导出仅 `OWNER` 可执行；领导或管理员如需导出，必须先取得该项目的 `OWNER` 授权或使用单独审批后的运维备份流程。
- 系统级完整备份不属于业务 API，由受控运维身份执行。
- 联系方式等个人信息只对具备项目读取权的用户显示，任何导出仍需按隐私规则处理。

## 7. API 操作映射

| API 操作类别 | 最低要求 |
| --- | --- |
| 查询项目列表 | 登录有效；普通用户按成员关系过滤，领导和管理员全局返回 |
| 查询项目详情 | 项目读取权 |
| 创建项目 | `ADMIN`，且请求中指定首位 `OWNER` |
| 编辑项目基础资料 | 项目 `OWNER`、`EDITOR` 或 `ADMIN` |
| 新增、修改、删除子记录 | 项目 `OWNER`、`EDITOR` 或 `ADMIN` |
| 管理项目成员 | 项目 `OWNER` 或 `ADMIN` |
| 归档项目 | 项目 `OWNER` 或 `ADMIN` |
| 恢复归档项目 | 项目 `OWNER` 或 `ADMIN` |
| 预览或下载文件 | 项目读取权；生成短时授权地址并记录审计 |
| 导出完整项目 | 项目 `OWNER` |
| 查看项目审计 | 项目 `OWNER`、`LEADER` 或 `ADMIN` |
| 管理用户和系统配置 | `ADMIN` |
| 推送离线操作 | 按操作发生时的当前账号与项目权限重新校验 |
| 拉取同步变化 | 只返回当前仍有读取权的项目变化 |

## 8. 权限变化与离线客户端

### 8.1 账号停用

- 服务端立即撤销该账号全部会话。
- 后续登录、读取、写入、文件授权和同步请求全部拒绝。
- 在线桌面端收到拒绝后退出账号并锁定本地业务界面。
- 本地凭证从系统安全存储中移除。

### 8.2 项目权限取消

- 服务端从权限变更提交序号开始停止返回该项目业务数据。
- 客户端下次同步收到 `PROJECT_ACCESS_REVOKED` 指令。
- 客户端在同一事务中标记项目不可访问，移除业务数据和本地文件缓存。
- 尚未上传的该项目操作标记为“权限已失效”，不得继续自动重试。
- 客户端仅保留操作标识、失败原因和时间，不保留被拒绝操作的业务载荷。

离线设备在获知权限变化前可能继续显示旧缓存，这是离线系统无法完全避免的窗口。登录凭证必须有有效期；到期后设备必须联网续期，无法无限期离线访问。

### 8.3 系统角色变化

- 系统角色变化后，服务端按账号当前角色处理后续 API 和同步操作，不信任客户端缓存的旧角色。
- 管理员角色被撤销后，未加入项目的待同步写操作按新角色重新校验；不再具有项目编辑权时拒绝并停止自动重试。
- 角色变化必须撤销或刷新现有会话，并记录角色调整及被拒绝操作的审计信息。

## 9. 判定示例

| 编号 | 场景 | 结论 |
| --- | --- | --- |
| 1 | 普通用户不是项目成员，查询项目详情 | 拒绝 |
| 2 | `VIEWER` 查询本人项目合同 | 允许 |
| 3 | `VIEWER` 修改本人项目合同金额 | 拒绝 |
| 4 | `EDITOR` 新增本人项目回款 | 允许 |
| 5 | `EDITOR` 增加项目成员 | 拒绝 |
| 6 | `OWNER` 增加 `VIEWER` | 允许 |
| 7 | `OWNER` 移除最后一名 `OWNER` | 拒绝 |
| 8 | 领导查看未参与项目的造价资料 | 允许，只读 |
| 9 | 领导修改未参与项目的造价版本 | 拒绝 |
| 10 | 管理员创建项目并指定负责人 | 允许 |
| 11 | 管理员修改未参与项目的回款金额 | 允许并记录审计 |
| 12 | 管理员停用用户 | 允许 |
| 13 | 普通成员下载本人项目附件 | 允许并记录审计 |
| 14 | 领导下载任意项目附件 | 允许并记录审计 |
| 15 | 用户离线修改后被取消权限，再上传修改 | 拒绝并标记权限已失效 |
| 16 | 被停用用户使用未过期的旧访问令牌同步 | 拒绝，因为服务端同时检查账号状态 |
| 17 | `OWNER` 导出本人项目完整数据 | 允许并记录审计 |
| 18 | 管理员直接导出未参与项目完整数据 | 拒绝，改走受控备份流程 |
| 19 | 管理员离线修改未参与项目后被撤销管理员角色，再上传修改 | 拒绝并标记权限已失效 |

## 10. 验收检查

- 任意 API 操作均能映射到第 7 节中的唯一规则。
- 系统角色与项目成员角色职责不混淆。
- 领导的全局查看权不扩大为全局编辑权。
- 管理员无需项目成员关系即可全局新增、修改和逻辑删除业务数据。
- 权限取消会同时影响 API、同步和文件访问。
- 至少覆盖第 9 节全部示例的自动化授权测试。
